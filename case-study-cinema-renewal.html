CASE 03 / COMMERCE

CGV 차세대
리뉴얼

여러 매장 채널과 결제 수단이 만나는 차세대 서비스에서 통합결제 화면을 구현하고, 정상 결제만큼 중요한 취소·실패·재시도 경험을 구조화했습니다.

기간2025.01 — 2025.05
형태매장 연계 웹 서비스
범위프론트엔드 개발

공개 범위 안내. 계약 및 보안 정책에 따라 내부 채널명, 결제사별 상세 규칙, API 명세, 실제 화면과 거래 데이터는 일반화했습니다.

01 / 문제

결제 완료 한 화면 뒤에 숨어 있는 수많은 분기

통합결제는 상품, 매장 채널, 결제 수단, 승인 결과에 따라 처리 방식이 달라집니다. 승인 지연이나 부분 실패처럼 화면과 서버 상태가 엇갈리는 순간에도 사용자가 중복 결제를 만들지 않도록 안내해야 했습니다.

02 / 내 역할

거래 상태를 이해할 수 있는 화면 흐름으로 구현

프론트엔드 개발자로 참여해 매장 채널과 통합결제 API를 화면에 연결하고, 정상·실패·취소·재시도 시나리오를 컴포넌트와 상태 흐름으로 구현했습니다.

  • 결제 UI: 선택한 상품과 수단, 최종 결제 정보를 단계별로 확인하도록 구성
  • API 연동: 요청·승인·결과 상태를 화면 피드백과 연결
  • 예외 협업: 백엔드·결제·QA 담당자와 오류별 사용자 행동 및 재현 조건 조율

03 / 핵심 구현

중복 거래를 막고 복구할 수 있는 결제 상태

  • 요청 잠금과 진행 피드백: 결제 처리 중 반복 입력을 제한하고 현재 상태를 분명히 표시했습니다.
  • 결과별 화면 분기: 승인·거절·취소·확인 필요 상태를 구분해 같은 오류 문구로 뭉개지 않도록 했습니다.
  • 복구 가능한 경로: 재시도 가능한 오류와 확인이 필요한 거래를 구분해 사용자의 다음 행동을 안내했습니다.

04 / 결과

매장 채널과 결제 시스템 사이의 안정적인 접점 구현

통합결제의 주요 화면과 API 흐름을 연결하고, 다양한 결제 결과가 발생해도 사용자가 현재 상태와 다음 행동을 이해할 수 있는 예외 처리 기반을 마련했습니다.
