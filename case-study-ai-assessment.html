CASE 02 / ASSESSMENT

AI 기반
학력진단평가

출제자·관리자·응시자가 서로 다른 목적과 권한으로 사용하는 평가 플랫폼에서 복잡한 업무를 역할별 화면과 안정적인 상태 흐름으로 정리했습니다.

기간2025.06 — 2026.02
형태웹 평가 플랫폼
범위프론트엔드 개발

공개 범위 안내. 발주 기관의 내부 정책, AI 모델·평가 알고리즘, 문항 데이터, 관리자 화면과 운영 수치는 비공개로 두고 공개 가능한 제품 구조만 설명합니다.

01 / 문제

한 시스템 안에 겹쳐 있던 세 가지 업무 맥락

문항을 만드는 사람, 평가를 운영하는 사람, 실제로 응시하는 사람은 필요한 정보와 실수의 비용이 달랐습니다. 문제은행·저작도구·평가 진행 상태가 연결되면서 화면의 조건과 데이터 의존성도 빠르게 복잡해졌습니다.

02 / 내 역할

역할과 권한을 화면 구조와 상태 모델로 번역

프론트엔드 개발자로서 요구사항을 사용자 역할과 작업 단계로 나누고, 문제은행과 저작도구를 포함한 주요 화면 및 API 연동을 구현했습니다.

  • 역할별 UI: 출제자·관리자·응시자에게 필요한 기능과 접근 조건 분리
  • 복합 상태 관리: 문항 작성·검토·배치와 평가 진행 상태를 화면에 일관되게 반영
  • 협업 기준: 기획·백엔드·QA가 같은 상태 정의와 예외 시나리오를 사용하도록 정리

03 / 핵심 구현

복잡도를 사용자에게 그대로 노출하지 않는 도구

  • 문제은행 탐색: 많은 문항을 조건에 따라 찾고 선택할 수 있도록 검색·필터·선택 상태를 구조화했습니다.
  • 저작도구 상태: 입력 중인 내용과 서버 데이터의 경계를 분리해 편집·저장·검증 피드백을 명확히 했습니다.
  • 응시 흐름 보호: 진행 상태와 제출 조건을 화면에서 예측할 수 있게 하고, 이탈이나 잘못된 조작에 대응하는 경로를 구성했습니다.

04 / 결과

역할별 업무가 하나의 제품 안에서 이어지는 기반 구축

문항 제작부터 평가 운영과 응시까지 이어지는 주요 화면을 구현하고, 권한과 작업 상태가 많은 평가 업무를 역할별로 구분된 사용 경험으로 정리했습니다.
